# 이음케어 React 프론트엔드

React + Vite로 구성한다. 대시보드·분석 실행/근거 검토·복지 추천·기획 요청 전달함을 제공한다. 평가·예산 화면과 실제 기획 Agent 연결은 후속 작업이다. 주소 해시로 탭을 이동한다.

## 설치·실행

Node.js 22.12 이상과 npm이 필요하다. 실제 검증 환경은 Node.js 24다. Python 환경과 API 키는 기존 프로젝트 설정을 사용한다. 비밀 키는 루트 `.env`에만 두며 `VITE_` 환경 변수로 옮기지 않는다.

프로젝트 루트에서:

```powershell
cd frontend
npm ci
npm run build
cd ..
python backend/server.py
```

<http://127.0.0.1:5175/#recommendations>에서 확인한다. Python 서버는 `frontend/dist`만 제공한다. React 화면 수정 후에는 `npm run build`를 다시 실행한다. node_modules·dist는 Git에 올리지 않으며 package.json과 package-lock.json을 함께 커밋한다.

개발 중에는 두 터미널을 사용한다.

```powershell
# 터미널 1: 프로젝트 루트
python backend/server.py
```

```powershell
# 터미널 2: 프로젝트 루트
cd frontend
npm run dev
```

개발 화면은 <http://127.0.0.1:5173/#recommendations>이다. `/api`만 5175 Python 서버로 전달한다. 5173과 5175는 주소가 달라 브라우저 저장 결과도 별도로 유지된다. 기존 결과가 없다고 자동 재조회하지 않는다.

## 파일

```text
frontend/

├─ vite.config.js                   # 개발 API 프록시·빌드·테스트 설정
└─ src/
   ├─ main.jsx                      # React 마운트·스타일 연결
   ├─ App.jsx                       # 공통 메뉴·페이지·기획 전달함
   ├─ useWelfare.js                 # 분석 수신·순차 추천·중지·결과 저장
   ├─ domain.js                     # API·계약·검토표·기획 요청 변환
   ├─ dashboard.js                  # 분석 결과의 집단별 요약·단위 표시
   ├─ styles.css                    # 기존 초록 계열 디자인·반응형 스타일
   ├─ components/
   │  ├─ Dashboard.jsx / Dashboard.css # 대시보드 화면·반응형 스타일
   │  ├─ Dashboard.test.jsx         # 집계·필터·추천 연결 검사
   │  └─ RecommendationParts.jsx    # 대상 설정·분석 목록·자원 카드·기획 준비
   ├─ App.test.jsx / domain.test.js # React 동작·데이터 계약 자동 검사
   └─ test-setup.js                 # 화면 테스트 초기화
```

## 현재 동작과 정리한 기능

- 분석 탭의 ‘분석 보고서 보기’는 선택 집단을 한국어 문서로 보여준다. 수치·단계 기준·원인 가설·공식 출처·AI 인용 채택/탈락·한계·다음 조치를 담는다. HTML로 내려받아 브라우저에서 열거나 미리보기의 ‘인쇄 / PDF 저장’을 사용한다. JSON은 ‘개발·연동용 데이터’에 별도로 둔다. 보고서는 현재 화면과 같은 검증된 배치에서 만들며 추가 검색·LLM을 호출하지 않는다. 보고서 생성은 src/analysisReport.js에 있다. HTML 내용은 이스케이프하고 스크립트 실행을 차단한다.

- 분석(`/#analysis`)은 고정된 준비 입력을 재계산하고 원본·순위 검증을 통과한 결과만 공개한다. 기준월별 재계산은 외부 API0회다. 선택한 완료 집단의 외부 검토는 별도 전송 확인 후 실행하며, Gemini계획/검토 최대2회·Tavily최대3회·문서GET최대4회다. 실행은 서버에서 비동기로 처리하고 화면은 상태만 조회한다. 분석과 실시간 복지추천은 하나의 실행 슬롯을 공유한다.
- 관측 수치·가설·검색 필요 판단·공식 출처·본문 수집 상태·인용 탈락 이유·API시도 횟수를 구분해 표시한다. 선택 집단의 검토를 다른 집단에 표시하지 않는다. 분석 완료 뒤 대시보드와 추천 입력을 함께 다시 읽고, 배치가 다르면 이전 추천 입력으로 이동하지 않는다. 실패 시 마지막 검증 결과를 유지한다. 원본 업로드·수치의 웹 자동 병합·2차 순위 확정은 제공하지 않는다.
- 분석 화면은 `src/components/Analysis.jsx`·`Analysis.css`에 있고, 실행·조회는 `backend/analysis.py`와 `/api/analysis/result`, `/api/analysis/job`, `POST /api/analysis/runs`가 담당한다. 서버 재시작 시 작업 상태 표시는 초기화되며 완료 결과는 파일에 남는다. 서버 재시작은 진행 중인 외부 검토가 끝난 뒤 수행한다.

- 대시보드(`/#dashboard`)는 기존 `/api/welfare/analysis-inputs`와 같은 검증된 최신 분석 배치를 사용한다. 새 API·검색·모델 호출 없이 기준월, 지역·성별 필터, 완료/부분/보류 집단 수, 완료 판정의 1~5단계 분포, 지역×성별×연령 표와 원래 공동 순위를 표시한다. 관측이 없는 칸은 자료 없음으로 표시하며 부분·보류를 1단계로 바꾸지 않는다. 합산 집단을 남녀 개별 집단에 중복 추가하지 않는다.
- 대시보드 화면은 `src/components/Dashboard.jsx`와 `Dashboard.css`, 집계·단위 변환은 `src/dashboard.js`에 있다. 수치 근거의 ratio는 100을 곱해 %로 표시하며 percent는 그대로 표시한다. 카드·통신 감소만으로 실제 고립·복지 자격을 확정하지 않는다. 최신 기준월 한 개만 연결되어 과거 월 선택·추이 그래프·데이터 업로드는 아직 제공하지 않는다. 완료 집단에서 ‘복지 추천으로 이동’을 누르면 원래 입력을 선택하고 탭을 이동하며 실시간 추천은 사용자가 별도 실행한다.

- ‘담당자가 확인한 지원 필요’ 체크박스는 지원 목적과 중복되어 제거했다. 담당자는 지원 목적만 선택한다. 팀원의 연결 입력에 이미 있는 `confirmed_support_needs`는 그대로 전달하고, 지역·연령·성별을 바꾸어 일반 탐색하면 빈 목록을 전달한다. 선택한 지원 목적을 확인된 필요로 자동 변환하지 않는다.

- 화면은 실시간 Tavily·Gemini 추천만 제공한다. 저장 자료 테스트 모드, 예시 위험도 버튼, 수동 JSON 입력은 제거했다. 집단 선택은 팀원의 분석 결과를 사용하며 지역·연령·성별을 직접 바꾸면 분석 없이 일반 탐색한다.
- 분석 수신·집단 선택·화면 진입은 검색·LLM을 실행하지 않는다. 일괄 추천은 첫 오류에서 중지하며 자동 재시도·다른 모델 전환·저장 자료 대체는 하지 않는다.
- 같은 배치·조건의 실시간 결과만 브라우저에서 복원한다. 과거 offline 결과는 실시간 결과로 복원하지 않는다. 성공 0개도 일괄 실행에서 건너뛰며 개별 추천 버튼은 새 조회다. 선택 자원·기획 프롬프트는 브라우저에 저장하지 않는다.
- 2차 대응 검토표는 후보 확보·미확보·실패·미조회를 구분한다. 위험 단계·1차 순위는 유지하며 최종 지원 순위를 확정하지 않는다.
- 기획 요청 미리보기·JSON 내려받기·서버 검증·로컬 전달함 저장을 유지한다. 실제 기획 Agent는 연결 전이며 기획서는 생성하지 않는다. 요청을 수정하면 이전 미리보기를 폐기한다.
- Python의 offline 조회·그래프 테스트용 엔진은 팀원 코드·자동 검증에 사용되어 유지했다. 화면의 불필요한 테스트 조작만 제거했다. 구형 DOM 테스트는 실제 React 테스트로 교체했다.

## 검증

```powershell
cd frontend
npm test
npm run build
```

자동 테스트는 외부 검색·모델을 호출하지 않는다. API 입력·기획 요청 형식은 [복지 추천 문서](../docs/welfare_agent.md)를 참고한다.
