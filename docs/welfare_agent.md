# 복지자원 추천 Agent

기본 경로는 **지역·연령·목적 → Tavily 공식 자료 검색 → 분석 결과와 Gemini 추천 판단 → 출처·조건 대조 → 화면과 기획 전달 데이터**다.
고정 목록 조회는 offline 테스트 모드로 분리했다. 실제 위험도 자동 수신과 프로그램 기획 Agent는 연결 전이다.
정제·위험도 계산과 프로그램 기획 로직은 변경하지 않는다.


## Tavily + Gemini 설정과 검증 범위

프로젝트 루트 `.env`에 다음 항목을 설정한다. 실제 키는 Git·채팅에 올리지 않는다.

```dotenv
TAVILY_API_KEY=발급받은_Tavily_키
GEMINI_API_KEY=발급받은_Gemini_키
GEMINI_MODEL=gemini-3.5-flash-lite
```

Tavily는 Free 플랜, Google AI Studio는 결제가 연결되지 않은 무료 등급을 유지한다. 앱은 두 계정의 결제 등급을 확인하거나 변경하지 않는다. 유료 계정의 키라면 같은 호출이 과금될 수 있다.

페이지 진입·새로고침에는 외부 검색·모델을 호출하지 않는다. 버튼 클릭 시 Tavily `/search` 기본 검색 최대 1회와 Gemini `generateContent` 판단 1회를 실행한다. 같은 검색은 아래 임시 캐시를 재사용할 수 있다. `search_depth=basic`, `auto_parameters=false`로 고정하고 Tavily 답변 생성·추가 원문 추출은 요청하지 않는다. 기본 검색은 현재 요청당 1크레딧이다. 자동 재시도·심화 검색·다른 모델·저장 목록으로의 대체는 없다. 검색 한도(402/429/432/433)나 Gemini 한도(429)에 도달하면 중단한다.

키는 서버에서만 읽는다. Tavily에는 지역·연령대·목적 검색어만, Gemini에는 이 조건과 검색 내용·전달받은 집단 위험도·선택적인 담당자 확인 정보를 전송한다. 원본 파일은 읽거나 전송하지 않는다. 자유 입력에는 공유 가능한 집계 결과만 사용하며 개인 식별 정보를 넣지 않는다. Tavily 키는 고정 검색 API의 Authorization 헤더, Gemini 키는 고정 API의 x-goog-api-key 헤더로만 전송한다. 브라우저 상태 API는 두 키의 설정 여부만 반환하며 인증 성공·무료 등급을 보증하지 않는다.

자동 테스트는 가짜 검색·모델 응답으로 호출 분리, 공식 URL 대조, 조건 제외, 보류 전달, 키 누락·한도·오류 중단을 검증한다. 실제 호출 결과와 추천 품질은 별도 검증이 필요하다.

## 실시간 Agent의 판단 범위

Tavily가 지역·연령·목적으로 검색하고, Gemini가 검색 결과와 분석 결과·선택적 추가 정보를 대조해 최대 5개 검토 후보를 판단한다. 관계 형성/일상생활/정서/경제·생활 안정/기타·통합 안내는 화면 분류이며 고정 신호 매핑이 아니다. 체크박스는 선택적인 추가 정보이고 필수 게이트가 아니다. 분석이 없으면 지역·연령·목적에 따른 추천이라고 설명하도록 지시한다.

Tavily의 include_domains에 선택 지역 공식 사이트(chuncheon.go.kr 또는 gangnam.go.kr), bokjiro.go.kr, mohw.go.kr을 지정한다. 반환 결과에서도 허용된 HTTPS 공식 URL인지 다시 검사한다. 최대 8개 결과 중 내용이 있는 중복 없는 출처만 사용하고, 각 검색 내용은 최대 6,000자로 제한한다. 링크를 직접 수집·추출하는 추가 호출은 없다. Gemini가 반환한 source_url이 실제 검색 출처에 없으면 제외한다. 다른 지역, 명확한 연령 불일치, 종료 표시, 중복 후보도 제외한다. 초기 도메인은 모든 공공·민간 자원을 포괄하지 않으며 내용은 검색 발췌문 수준이다.

검색 출처 URL 일치는 원문 전체의 사실·최신성 검증이 아니다. 미명시 연령·지역 제공 여부·지난 공고 해석을 LLM이 틀릴 수 있어 담당자 검토가 필요하다. 신뢰할 검색 근거가 없거나 응답이 불완전하면 오류 또는 빈 결과를 보여주며 고정 목록으로 성공처럼 대체하지 않는다. 출처 등의 검사로 후보가 제외되면 제외된 자원을 언급할 수 있는 원래 AI 요약도 표시하지 않는다.

LLM 설명·추가 질문·검색 출처·관측 제한·예시 여부를 화면과 내보내기에 보존한다. 위험 단계 계산과 개인의 진단·고립 확률·자격 확정은 이 Agent의 역할이 아니다. 보류/불완전 상태는 응답 구조에서 보존하며 LLM에도 해석 제한으로 전달한다.

공식 구현 근거: [Tavily 검색](https://docs.tavily.com/documentation/api-reference/endpoint/search), [Tavily 크레딧](https://docs.tavily.com/documentation/api-credits), [generateContent](https://ai.google.dev/api/generate-content), [구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output), [무료 등급·검색 요금](https://ai.google.dev/gemini-api/docs/pricing).

## Gemini 일시 중단(503)과 수동 재시도

Gemini 5xx 오류는 30초 후 수동으로 재시도할 수 있도록 retry_after_seconds=30을 반환한다. 화면은 그동안 추천·재시도 버튼을 잠시 비활성화한다. 시간이 지나도 자동 요청은 보내지 않는다. 30초는 과도한 연속 호출을 줄이기 위한 대기 시간이며 서버 복구를 보장하는 시간은 아니다. 429는 자동 재시도하지 않으며 무료 할당량을 확인해야 한다.

Tavily 공식 검색 결과는 서버 메모리에 최대 16개, 5분간 보관한다. 검색 조건과 인증 키의 해시가 같을 때만 재사용한다. 공개 검색 결과만 저장하며 위험도 입력·Gemini 판단·인증 키 원문은 보관하지 않는다. 검색 실패·공식 근거 없는 응답은 저장하지 않는다. 서버 재시작, 만료, 다른 검색 조건·키에서는 새 검색이 필요하다. 서로 다른 위험도라도 공개 검색 조건이 같으면 검색 결과만 재사용하고 Gemini에는 현재 위험도를 전달해 새로 판단한다.

Gemini 실패 뒤에도 이 검색 결과는 남아 있어 같은 조건으로 수동 재시도할 때 Tavily를 다시 호출하지 않는다. 재사용 시 최초 검색일을 유지하고 화면·내보내기에 search_cache_hit를 표시한다. 저장 자료 offline 모드와는 다른 개념이다.

## 추천 분류·설명·출처 표시

지원 분야(`purpose`)와 고립 예방 연관성(`isolation_relevance`)은 별개다. Gemini가 검색된 지원 내용에 따라 direct(교류·정기 안부 등 직접 연결), indirect(일반 생활 기반 지원), uncertain(연관성 근거 부족)을 구분하고 `relevance_reason`으로 설명한다. 분류는 AI 해석이며 실제 예방 효과나 개인의 고립 상태를 검증한 결과가 아니다. 서비스명을 이용한 고정 분류는 하지 않는다. 명시적으로 선택한 지원 목적과 다른 분류의 후보는 서버에서 제외한다.

카드는 추천 이유·고립 예방과의 연결·신청 전 확인을 나눠 표시한다. 위험도 입력이 없으면 지역·연령·목적 기반 추천이라는 안내를 서버가 고정 제공한다. 프롬프트에서 코드 용어 사용을 막고 표시용 설명에 남은 null/risk_assessment 표기도 읽기 쉬운 말로 치환한다.

실시간 출처의 checked_at은 **검색일**로 표시한다. 저장 자료 모드에서는 **출처 확인일**이며 새로운 검색을 했다는 뜻이 아니다. 자료 기준 연도는 별도 `source.reference_year`로 표시하고, 미확인은 최신 자료라고 추정하지 않는다. LLM이 제시한 연도와 240자 이내의 근거 구절이 해당 URL의 실제 검색 제목/내용에 있는지 대조한다. 근거가 없거나 다른 URL에만 있으면 연도와 인용문을 버리고 unknown으로 남긴다. 연도 구절의 의미까지 독립 검증한 것은 아니므로 상세 화면에 원문 인용과 한계를 함께 표시한다.

`source.reference_year_status`는 past_year/current_year/future_year/unknown이며 현재 연도라도 모집·자격이 검증됐다는 뜻이 아니다. 과거 연도는 현행 기준 재확인, 미래 연도는 적용 시점 확인으로 표시한다. page_updated_at은 여전히 별도 정보로 유지한다. 신규 필드는 선택 목록 JSON에도 보존되며 기존 HTTP schema_version(welfare-0.4)은 유지한다.

## 실행과 파일

프로젝트 최상위에서 `python backend/server.py` 실행 후 <http://127.0.0.1:5175/#recommendations> 접속.
추가 패키지 설치는 필요 없다. 실시간 모드는 두 API 키가 필요하고 offline 테스트는 키 없이 실행된다. `--port 5176`처럼 다른 포트를 지정할 수 있다.
서버는 로컬 개발용이며 127.0.0.1에서 frontend 폴더만 제공한다. 외부 배포용 서버가 아니다.

| 파일 | 역할 |
| --- | --- |
| `ai/welfare_agent/live_agent.py` | Tavily 검색·Gemini 판단·출처 대조 |
| `ai/welfare_agent/recommender.py` | 요청 검증·지역/연령대/목적 필터·일치 근거 |
| `ai/welfare_agent/welfare_resources.json` | 공식 안내에 근거한 자원 6개와 출처·확인 상태 |
| `backend/server.py` | 화면 및 JSON API 제공 |
| `frontend/app.js` | API 호출·로딩·오류/재시도·선택/내려받기 |
| `tests/test_welfare_agent.py` | 필터·계약·출처와 HTTP 연결 검증 |

## 요청 및 실행 모드

`POST /api/welfare/recommendations`, `Content-Type: application/json`

```json
{
  "mode": "live",
  "target": {"region": "춘천시", "age_group": 60, "purpose": "all"},
  "risk_assessment": null
}
```

- mode: live가 기본이다. offline을 명시할 때만 저장된 6개 자원을 조회한다.
- 지역: 춘천시 또는 강남구. 원본 관측 지역이 주민 거주지라는 뜻은 아니다. 개인 거주지를 확인해야 한다.
- 연령대: 정수 10/20/30/40/50/60. 각각 20대 미만/20대/30대/40대/50대/60대 이상. 개인 나이가 아니다.
- 목적: all/connection/daily/wellbeing/economic/other. economic은 경제·생활 안정, other는 기타·통합 안내다.
- 위험도: null이면 일반 조회. 객체가 있으면 아래 `risk-input-0.1` 초안 계약을 검증한다. 위험도 담당자와 최종 합의 전이다.
- `confirmed_support_needs`: 선택 입력, connection/daily/wellbeing/economic/other의 중복 없는 목록(화면 체크박스는 기타를 제외한 네 항목). 기본값은 빈 목록이며 담당자가 직접 확인한 필요만 전달한다.
- 지정되지 않은 필드·누락·다른 형식은 400. JSON 외 형식은 415, 본문 크기 제한은 16KiB.

## 응답 및 기획 전달

- HTTP 응답 `schema_version`: welfare-0.4. mode는 live/offline이다. 저장 자료 조회 함수의 내부 버전은 0.3이다.
- `is_demo`: false는 **자원 목록이 실제 공식 안내 기반**이라는 뜻이다. `has_example_context`가 true이면 위험도 맥락은 가상 입력이다. 둘은 구분해야 한다.
- live의 `recommendation_method`: tavily_search_gemini_judgment_v1, catalog_version은 null. model·search_provider·searched_at·search_query·search_credits·search_sources·excluded_count를 함께 반환한다. search_credits는 신규 검색 시 제공자 보고값이며 미제공 시 null이다. 캐시 재사용 시 search_cache_hit=true와 search_credits=0을 반환한다. offline에서는 기존 목록 버전과 필터 방식을 표시한다.
- `target`, `risk_assessment`: 조회 집단과 전달받은 위험도 결과. 위험 단계를 재계산하지 않는다.
- live의 review는 LLM 요약(summary)·추가 질문을 포함하며 rules_version은 llm-grounding-0.2다. input_note는 위험도 입력 유무에 따른 서버의 안내이며 LLM의 판단 요약과 구분한다. offline은 support-review-0.2 규칙을 사용한다.
- `resources`, `total`: 결과 목록과 개수. 일치가 없어도 정상 200, 빈 배열을 반환한다.
- `coverage`: candidates_found 또는 (live) no_grounded_candidates/(offline) no_candidates_in_catalog와 해석 설명. 후보가 없더라도 서비스 부재·지원 불필요 판정으로 해석하지 않는다.
- 각 자원: 식별자·지역·설명·지원 목적·조건·운영 방식·일치 근거(`match_reasons`)·확인 사항.
- `eligibility_status`: needs_confirmation. 개인 신청 자격은 판정하지 않는다.
- `age_match`: overlap(집단 연령 구간과 겹침)/partial(일부만 겹침)/unknown(미명시 기준). 어느 것도 자격 확정이 아니다.
- live의 source.type은 official_web_search, offline은 official_local_government다. URL·제목·확인일·검토 메모를 보존한다. 검색 출처 URL 대조가 원문 전체의 사실 검증을 의미하지 않는다.
- `application_method`: 공식 안내의 신청 절차 요약. 온라인 직접 신청 경로를 확정하지 않아 `application_url`은 null이다. 출처 URL을 신청 링크로 오인하지 않는다.
- `availability_status`: needs_confirmation. 현재 모집·예산·운영 확인 전이다.
- `warnings`: 과거 안내 가능성·현재 운영 미확인·자격/순위 미판정·미연동에 관한 주의사항.
- live의 support_basis는 llm_analysis_match다. offline은 staff_confirmed_need(담당자가 확인한 필요와 일치)/staff_requested_purpose(선택한 조회 목적)/general_browse(일반 조회). 어느 것도 효과·자격 확정이 아니다.

선택 목록 JSON은 응답 메타데이터와 주의사항을 유지하고 선택한 자원만 남긴다. `total`은 선택 개수로 바꾸고 `exported_at`을 추가한다. 기획 담당자가 향후 받을 데이터의 초안이며 현재는 로컬 파일만 생성한다.
화면은 조회 중 중복 요청을 막고, 실패를 빈 결과와 구분하며, 재조회 시 이전 선택을 제거한다. 결과는 HTML 문자열로 실행하지 않도록 이스케이프한다.

## 위험도 입력 계약 초안

다음은 실제 분석 결과가 아닌 연결 검증 예시다. 추천 화면의 **위험도 결과 연결 → 예시 입력 채우기 → 추천 자원 조회**로 확인할 수 있다.

```json
{
  "schema_version": "risk-input-0.1",
  "assessment_id": "example-only",
  "region": "춘천시",
  "age_group": 60,
  "period": "2025-12",
  "status": "complete",
  "level": 3,
  "signals": [{"type": "movement_decline", "description": "연결 검증용 이동 감소 예시"}],
  "limitations": ["실제 결과가 아닌 예시 입력"],
  "model_version": "example-model-not-production",
  "is_example": true
}
```

모든 필드를 요구한다. region·age_group은 target과 같아야 한다. period는 실제 달력의 YYYY-MM, status는 complete/partial/held이며 complete는 1~5 정수 level, held는 null level이다. partial은 알려진 하한 단계 또는 null을 허용한다. 신호 유형은 activity_decline/consumption_decline/movement_decline이며 설명 문자열과 함께 전달하고 유형을 중복하지 않는다. 모델 버전·분석 식별자·관측 제한과 예시 여부를 함께 보존한다. 값·필드·버전이 다르면 400으로 거절한다.

현재는 이 형식으로 직접 입력한다. 팀원의 CSV/JSON에 대한 자동 변환기나 데이터 재계산은 구현하지 않았다. 팀원 형식이 확정되면 별도 변환 지점을 마련한다. 입력을 비우면 위험도 없는 일반 조회로 돌아간다. 지역·연령을 바꾼 뒤 이전 집단의 위험도를 재사용하면 불일치 오류로 거절한다.

## 저장 자료 테스트 모드의 추천 기준과 검증 사례

이 표는 프로젝트의 검토용 규칙이며 효과가 검증된 정책·임상 기준이 아니다. 위험도 단계만으로 개인의 생활 결핍, 정신 상태, 경제적 어려움이나 자격을 추정하지 않는다.

| 조건 | 처리 |
| --- | --- |
| 위험도 없음 | 지역·연령·조회 목적의 일반 후보 조회 |
| 완료 + 활동/이동 감소 | 관계 형성 지원 필요를 확인해볼 **가설**과 참여 의사·접근성 확인 질문 표시. 자동 필터링하지 않음 |
| 완료 + 소비 감소 | 원인과 생활 지원 필요를 추가 질문. 생활 지원·상담 필요를 자동 생성하지 않음 |
| 보류/불완전 판정 | 신호 가설을 생성하지 않고 보류/불완전 상태와 확인 질문 표시. 자원 목록은 일반 탐색이며 담당자가 독립적으로 확인한 필요는 적용 가능 |
| 담당자 확인 필요 목록 + 전체 목적 | 확인한 목적에 해당하는 자원으로 좁힘. 개인 자격은 계속 needs_confirmation |
| 개별 조회 목적 선택 | 해당 목적을 탐색. 확인 필요 목록과 다른 목적이면 불일치 안내를 제공 |
| 위험 단계만 1에서 5로 변경 | 자원 목록·순위·자격을 바꾸지 않음 |

전체 목적에서 확인 필요가 비어 있으면 모든 목적의 후보를 유지한다. 명시적인 확인 없이 관계 형성 가설을 추천 사실로 전환하지 않는다. 관측 제한은 화면과 내보내기에 보존한다. 위험 판정과 지원 필요가 독립적이므로 보류를 '지원 불필요'나 '1단계'로 바꾸지 않는다.

팀원에게 확인할 내용은 집단 키·기준 월·완료/불완전/보류의 의미·단계 정의·신호 코드·관측 제한·모델 버전이다. 현재 코드는 위험도 입력과 검토 규칙의 초안이며 팀 합의 완료를 의미하지 않는다.

### 모델 선택 배경

Gemini 2.5 Flash·Flash-Lite는 신규 프로젝트에서 제공 중단(404)이 확인되어 더 이상 사용하지 않는다. Gemini 3.5 Flash-Lite의 무료 텍스트 입출력과 별도 Tavily 검색을 연결했다. Gemini의 Google 검색 도구는 요청하지 않는다.

### 실제 연결 확인 (2026-10-16)

공개 조건(춘천시·60대 이상)으로 1회 호출했다. Tavily에서 공식 출처와 검색 내용을 확보해 Gemini 판단 단계까지 진행했으나 Gemini가 HTTP 503을 반환했다. 자동 재시도는 하지 않았다. 이후 사용자가 실제 추천 후보 3개가 표시된 화면을 확인했다. 이번 분류·설명·연도 표시 변경은 가짜 응답 테스트로 검증했으며 변경 후 실호출 추천 품질 검토는 별도로 진행한다.

2026-10-17 연결 점검: Tavily 호출 없이 Gemini에 짧은 확인 요청을 1회 보내 HTTP 200/STOP을 받았다. 이는 키·모델의 현재 응답 확인이며 전체 추천 요청의 성공·안정성 보장은 아니다. 503 시 검색 캐시 재사용과 대기 후 수동 재시도는 가짜 응답으로 검증했다.
