# 데이터 정제 완료 기준과 재현 방법

## 실행 환경

Python 3.12 권장 (최소 3.11). 검증 환경은 Python 3.12.14, pandas 3.0.1, numpy 2.3.5이다.
Python 3.9 환경에서는 아래 고정 버전을 설치할 수 없으므로 3.12 인터프리터를 사용한다.
프로젝트 루트에서 환경을 준비한다.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts/data_processing/run_preprocessing.py
```

Codespaces 등 Linux에서는 `.venv/bin/python`을 사용한다.
원본은 Git에서 제외되므로 각 팀원이 `data/raw/`에 별도로 준비해야 한다.
pip 설치는 최초 환경 준비 단계이며 실행 파일이 자동으로 설치하지 않는다.

## 원본과 실행 순서

- 통신: `flow_age_pop_YYYYMM.csv`, `flow_time_pop_YYYYMM.csv`, `flow_wkdy_pop_YYYYMM.csv` 각 6개.
- 기간: 2025년 7~12월. 제공 기간 외 파일이나 누락 월이 있으면 중단한다.
- 카드: `신한카드_빅콘테스트2026_데이터1.txt`, `신한카드_빅콘테스트2026_데이터2.txt`.
- 통신 구분자는 `|`, 카드 구분자는 탭이며 카드 인코딩은 CP949이다.
- 통합 실행은 통신 정제 → 카드 정제 → 특징 결합 → EDA → 최종 검증 순서다.
- 실행 위치와 관계없이 스크립트 위치에서 프로젝트 루트를 계산한다.

## 확정한 처리 기준

| 항목 | 처리 |
| --- | --- |
| 통신 완전 중복 | 값까지 완전히 동일한 행만 제거. 제거 건수를 출력 |
| 서로 다른 값의 중복 키 | 합치거나 평균 내지 않고 오류로 중단 |
| 원본 숫자 | 결측·음수·무한대·변환 불가를 허용하지 않음. 카드 금액·건수는 정수 |
| 원본 카드 필수 정보 | 날짜·가맹점 지역·업종·성연령 결측을 허용하지 않음 |
| 카드2 거주지 결측 | 원본과 집계에 보존. 전체 소비 집계에서 제외하지 않음 |
| 카드1 법인 | 성별·연령 법인 표시 일치 확인 후 제외 |
| 카드2 법인 | 정의서와 달리 법인 기록이 있으면 중단 |
| 60대 이상 | 카드 60/70/80/90대를 통신의 60대 이상에 맞춰 집계 |
| 카드1·2 | 서로 다른 출처의 전체 합계를 유지하며 더하지 않음 |
| 통신 3종의 위치 차이 | outer 결합으로 보존. 특정 자료가 없는 위치를 0으로 채우지 않음 |
| 그룹별 카드 기록 없음 | 동일 키에 관측되지 않은 그룹의 건수·금액만 0 처리 |
| 첫 달·전월 0·누락 월 | 전월 변화는 NaN. 같은 위치의 인접한 월만 비교 |
| 통신 엔트로피 | 유동량 합계 0이면 분포를 해석할 수 없어 NaN |
| 해석보류·미분류 | 보존하며 사회활동 후보 합계에는 제외. 전체 건수 분모에서는 유지 |

## 결합 단위와 단위 해석

최종 한 행은 월×가맹점/유동인구 지역×연령대다. 현재 6개월×2지역×6연령 = 72행.
통신은 거주민 수·고유 방문자 수가 아니며 카드는 거주민만의 소비가 아니다.
시간대·요일 특징은 지역 공통값으로, 연령별 값이라고 해석하지 않는다.

- 통신 위치별 `FLOW_POP_PCT_*`: 백분율. -10은 10% 감소.
- 최종 `risk_features.csv` 변화율/비중/관측률: 비율. -0.1은 10% 감소.
- `비중전월차이`: 비중의 차이. -0.01은 1%p 하락.
- 통신 전월 변화는 두 월 모두 관측된 동일 위치만 비교한다.
- 관측률은 3종 결합 위치 중 해당 자료가 있는 비율이며 인구 대표성이나 정확도가 아니다.
- 카드 미분류 컬럼은 현재 모두 0이어도 신규 업종 대응을 위해 유지한다.

## 지역 매핑과 미해결 한계

소지역코드 앞 5자리의 통계청 지역코드로 11230→서울 강남구, 32010→강원 춘천시를 연결한다.
행정안전부 법정동 코드와 혼용하지 않는다. 근거 URL은 `build_risk_features.py`에 있다.
나머지 지역코드는 삭제하지 않고 통신 특징에 남기되 최종 카드 결합에서 제외한다.
`region_mapping_review.csv`에 모든 코드의 행 수와 UTM-K 좌표 범위를 기록한다.

**좌표와 실제 행정경계를 대조하는 공간 검증은 완료하지 않았다.** 현재 저장소에 경계 파일이 없다.
지역코드의 의미 확인과 좌표 기반 경계 검증은 별개다. 공식 무료 경계 자료를 확보하면
기준 연도·좌표계·사용 출처를 명시하고 점-경계 대조를 수행해야 한다.
따라서 현재 결과는 코드 기반 매핑으로 재현 가능한 탐색 특징이며 완전히 검증된 위험 모델은 아니다.
해석보류 업종의 정의, 계절성, 관측률 차이 역시 위험도 설계에서 반영할 과제다.

## 검증 결과와 공유

통합 실행의 최종 검증은 전체 키 조합, 그룹별 합계, 카드 특징 보존, 무한대,
예상 결측 위치, 비율 범위를 검사한다. EDA는 원본 품질과 재계산 일치도 확인한다.

`data/processed/preprocessing_manifest.json`에 실행 상태, 환경 버전, 분류 버전,
입력·코드·주요 결과의 SHA-256을 남긴다. `status: passed`는 데이터 계약 검증 통과이며,
미해결 해석 한계나 고립 분류 정확도 검증까지 통과했다는 뜻이 아니다.
실패 시 중간 결과를 모델 입력으로 사용하지 않고 문제를 해결한 후 전체 실행을 다시 한다.

```powershell
python -m unittest discover -s tests -v
```

Git에는 코드·환경 정의·문서·테스트만 올린다. 원본/생성 결과/검증 기록은 로컬에 보관한다.
정제 마무리는 main에서 커밋하고, 이후 위험도 개발부터 `hyeonji/risk-model` 브랜치를 사용한다.
