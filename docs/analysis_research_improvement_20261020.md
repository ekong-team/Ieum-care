# 질문별 외부 근거 보완과 한국어 분석 설명

## 무엇을 고쳤는가

사용자는 실제 검색·Gemini 출력 JSON을 보고 무엇을 수행했는지 이해하기 어렵다고 말했다. 기존 구현은 연결 시험과 근거 번호 선택이 중심이었고, 검색도 인구·경기·달력을 하나로 섞어 행정안전부 일반 안내 페이지 한 개만 확보했다. 새로운 원인·수치 데이터를 확보한 결과가 아니었다.

이 문제를 다음과 같이 개선했다.

| 기존 문제 | 변경한 동작 | 이유 |
|---|---|---|
| 검색어 하나에 여러 질문 혼합 | 인구·지역 경기·달력 세 질문으로 검색 | 필요한 정보를 분명하게 드러내기 위해 |
| 분석월 말일 뒤에 발표된 통계까지 제외 | focused 모드는 검색 실행일까지 발표된 사후 자료도 탐색 | 12월 통계가 다음 해 1월에 나올 수 있으므로 |
| 일반 홈페이지도 모델이 선택 가능 | 홈페이지·지역·기준월·주제의 최소 적합성 검사 | 단순 출처 선택을 분석 근거 확보로 오해하지 않도록 |
| 모델이 근거 번호만 선택 | 질문별 인용 문장과 관련성 해석을 선택적으로 생성 | 어떤 질문을 보완했는지 설명하기 위해 |
| 외부 문장을 그대로 수용할 위험 | 실제 발췌 내 인용·질문·출처 번호 대조 | 없는 인용과 부적합 자료의 근거 승격 방지 |
| JSON 실행 기록만 제공 | `analysis_explained.md` 자동 생성 | 사람이 결과·판단 이유·미확인 사항을 읽도록 |

코드의 적합성 검사는 문자열 기반 최소 검사다. 숫자의 단위·통계 표본·실제 인과관계를 독립적으로 검증하는 기능이 아니다. 결과는 항상 참고 후보로 표시하며 위험 단계나 우선순위에 자동 반영하지 않는다.

## 먼저 볼 실제 결과 설명

`data/processed/analysis_research_preview_20261020/previous_live_explained.md`

이 파일은 앞서 승인받아 실행한 실제 Tavily1회·Gemini1회 결과를 설명 형식으로 바꾼 것이다. 새 검색 결과나 가상의 검색 성공을 추가하지 않았다.

- 대상: 2025년12월 춘천30대여성.
- 카드 일평균 변화 −6.62%, 관측 유동량 −4.57%, 연속 비교2회로 기존 규칙4단계.
- 기존 주민등록 인구 16,633→16,636명(+0.018%), 해당 월31일·주말/공휴일 합계9일.
- 인구는 거의 유지되지만 활동 지표는 감소했다. 인구·활동지역 자료의 대상이 달라 인구를 활동량 분모로 쓰거나 원인으로 확정하지 않는다.
- 앞선 웹 검색이 추가한 구체적인 인구·경기·달력 근거는0개다. 홈페이지 한 개를 얻었다는 사실을 분석 개선으로 포장하지 않는다.

## 새 실행 방식

기존 `basic` 모드는 검색1회+모델1회 동작을 유지한다. 새 `focused` 모드는 같은 단일 집단에 대해 다음을 실행한다.

1. 인구 변화에 관한 공식 통계표·보고서 검색1회.
2. 지역 경기·소비에 관한 공식 보고서 검색1회.
3. 전국 공휴일·해당 기간 일정 관련 검색1회.
4. Gemini가 기존 프로필·이미 확보한 인구/달력 배경·검색 발췌를 읽고 확인할 근거·가설·질문과 외부 참고 후보를 선택한다.

검색은 최대3회, Gemini는 최대1회다. 무료 한도나 인증 오류(401/403/402/429/432/433)가 나오면 남은 검색은 실행하지 않는다. 다른 질문 검색을 같은 실패 요청의 자동 재시도로 사용하지 않는다. 결과가 없거나 검색이 실패하면 내부 근거만 검토할 수 있지만 보완 근거가 확보됐다고 표시하지 않는다.

검색 발췌는 질문당최대3개·합계최대9개다. 소스 수신·인용·시도 횟수를 기록한다. 실제 비용0원을 가정하지 않으며 계정 등급과 한도는 제공자 대시보드에서 확인한다.

## 시간·지역·주제 검사

- focused는 사후 해석용이다. 분석 기준월과 발표일을 따로 표시하고, 기준월 이후 발표된 자료는 `publication_after_target_period`로 표시한다.
- 통계 발표일과 통계 대상 기간은 서로 다르다. 실행일까지 발표된 자료를 허용한다고 해당 월 통계라는 것이 보장되지 않는다.
- 일반 루트 홈페이지와 index/main 페이지는 탐색 경로로만 남긴다.
- 발췌·제목에 대상 기준월, 대상 지역, 질문 주제 표현이 있고 상세 페이지 형식이면 `reference_candidate`로 분류한다.
- 전국 공휴일 자료는 지역명이 없어도 해당 월·공휴일 표현·상세 페이지 조건을 통과하면 참고 후보가 될 수 있다.
- 달력의 공식 탐색 도메인에 한국천문연구원 `kasi.re.kr`를 포함했다. 공식 [천문우주 정보](https://astro.kasi.re.kr/)의 달력자료·월력요항 메뉴를 확인했다.
- 구조화 통계표의 행·열 값을 직접 읽지 않고 검색 발췌만 확인하므로, 자동 수치 병합에 사용하지 않는다.

## 모델이 만들 수 있는 내용과 제한

기존 `observation_ids`, `hypothesis_codes`, `question_codes`, `source_ids`와 추가 `findings`를 사용한다. findings에는 다음이 있다.

- `question_id`: population/economy/calendar 중 하나.
- `source_id`: 실제 제공된 공식 발췌 번호.
- `quote`: 발췌에서 그대로 가져온20~400자 인용.
- `relevance`: 해당 질문과의 관련성·남은 한계를 설명하는 한국어 문장.

프로그램이 출처 선택 여부, 질문과 출처의 일치, 최소 적합성 검사, 발췌 내 인용 존재를 확인한다. 실패한 인용은 `rejected_findings`에 사유를 기록하며 보고서의 보완 내용으로 사용하지 않는다. 모델의 관련성 해석은 독립 사실 검증 전 해석이라고 명확히 표시한다. 모델이 만든 문장을 공통 프로필의 새 수치 근거로 넣지 않는다.

저장 후 검증에서도 범위·인용 검사를 재수행하고 설명 보고서가 저장된 결과에서 재생성되는지 확인한다. 새 텍스트를 위험 점수나 팀 프로필에 자동 합치는 기능은 없다.

## 출력

```text
지정한 출력 폴더/
├─ latest.json
└─ 실행해시/
   ├─ analysis_bundle.json
   ├─ external_research.json
   ├─ analysis_explained.md       # 사람이 먼저 읽을 파일
   ├─ profiles/
   ├─ priority_review.json
   └─ verification.json
```

설명 보고서는 다음을 보여준다: 원래 데이터의 수치 → 단계 판단 이유 → 이미 가진 인구·달력 배경 → 검색 질문 → 인용 후보와 모델 해석 → 근거로 쓰기 어려운 자료 → 여전히 모르는 것 → 담당자 확인 사항.

## 실행 명령과 전송 검토

```powershell
./.venv-agent/Scripts/python.exe -X utf8 -B scripts/integration/run_analysis_agent.py --input-folder data/processed/analysis_sex_inputs_20261019 --output data/processed/analysis_research_live_20261020 --period 202512 --mode gemini --web-search --research-mode focused --analysis-id 202512_32010_30G_female --allow-external
```

이 명령을 문서에 적었다고 실제 실행한 것은 아니다. 현재 새 focused 실제 호출은 승인 전0회다. 앞선 승인은 기존 집단 요약·각API1회 시험 범위였으므로 이번에 늘어난 검색 횟수와 인구·달력 배경 전송 범위를 구체적으로 확인한다.

`data/processed/analysis_research_preview_20261020/proposed_requests.json`에 인증 헤더 없는 구체적 요청 미리보기를 만들었다. Tavily에는 세 공개 검색어만 보낸다. Gemini에는 기존 춘천30대여성 요약에 이미 확보한 주민등록 인구16,633→16,636명과 달력 배경(31일·주말공휴일9일 등), 기존 관측 해석과 공식 발췌최대9개를 보낸다. 원본·좌표·개인 식별정보·전체 집단 자료·키는 본문에 넣지 않는다. 무료 Gemini 데이터 이용 안내는 이전 연결 문서와 같다.

## 검증과 현재 상태

- 새 코드: `ai/analysis_agent/research.py`, `gemini_provider.py`의 focused 경로, 실행·저장·검증 옵션.
- 테스트: `tests/test_analysis_research.py`의 질문 분리·홈페이지 차단·지역/기준월 불일치·전국 휴일·실재 인용·가짜 인용·잘못된 출처·호출 상한·부분 실패·한도 중단·수치 보존·보고서 검사.
- 관련 회귀 테스트147개 통과. 실제 API를 호출하는 테스트는 아니다.
- 사용자에게 사람이 읽는 기존 실제 실행 설명과 새 전송 미리보기를 제공한다. focused의 실제 검색 품질·모델 반응은 승인 후 확인해야 한다.
- 기존 실제 결과는 당시 구현의 기록으로 보존한다. 새 코드는 새 출력 폴더를 사용하고 이전 파일 해시를 임의 수정하지 않는다.
- 실제 새로운 숫자 데이터 추가·사회적 고립 원인 확정·다른 팀 Agent 연결 완료·Git push를 수행한 것으로 표현하지 않는다.
