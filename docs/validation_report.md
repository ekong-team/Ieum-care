# 실제 호출 검증 보고서 — 기획 그래프

작성: 김정욱 · 실행일: 2026-10-26 · 설계 문서 [12장 검증 계획](system_design.md)의 "실제 호출"·"사람 검토" 항목

이 문서는 실제 Gemini·Tavily 호출로 기획 그래프(원인 분석 → 기존 자원 확인 → 사례 검색 → 공백 분석 → 기획 생성 → 근거 검증 → 평가·재기획 → 리포트)를 실행한 결과다.
자동 테스트 통과율이나 평가 점수를 기획 품질로 보고하지 않는다. 점수는 규칙이 무엇을 확인했는지를 보여 줄 뿐이며, 품질 판단은 6장의 사람 검토로 한다.

## 1. 실행 방법

```powershell
python scripts/integration/run_validation.py          # offline 확인 (외부 호출 0)
python scripts/integration/run_validation.py --live   # 실제 호출 (이번 실행)
```

- 대상 프로필·원인 가설: 최신 분석 결과(`analysis_current`, 2025-12 기준)의 집단을 그대로 쓴다. 직접 입력이 아니다.
- 복지 추천·사례 검색·기획 생성·평가: 화면의 통합 실행과 같은 기본 엔진을 쓴다.
- 대상 4개: 설계 12장의 춘천·강남 × 20대·60대 이상. 분석 결과가 성별로 나뉘어 있어서 강남 20대는 1차 순위가 더 높은 남성(3위)을 골랐고, 나머지는 성별이 한쪽으로 몰리지 않게 번갈아 골랐다.
- 대상마다 1회만 실행했다(사용자 승인 범위). 같은 대상을 다시 실행하면 LLM 출력이 달라질 수 있으므로, 아래 숫자는 1회 표본이다.
- 원본 결과: `data/processed/validation_20261026/` (Git 제외). `live_summary.json`에 아래 표의 숫자가, `live_<집단ID>.json`에 전체 실행 상태와 판단 기록이 있다.

## 3. 호출 수와 시간 (1회 실행 기준)

| 노드 | Gemini | Tavily | 공식 문서 GET | 시간 |
| --- | --- | --- | --- | --- |
| 사례 검색 | 0 | 2 | 0 | 3.5~4.5초 |
| 기존 자원 확인(복지 추천) | 1 | 1~2 | 2~4 | 10.2~24.4초 |
| 기획 생성 | 1 | 0 | 0 | 7.1~9.2초 |
| 평가(실현 가능성 축) | 1 | 0 | 0 | 1.8~2.8초 |
| **합계** | **3** | **3~4** | **2~4** | **20.5~33.5초** |

- 4회 합계: Gemini 12회, Tavily 14회, 공식 문서 GET 11회. 호출 수는 요청 시도 수이며 청구 크레딧·토큰이 아니다.
- 시간의 절반 이상은 복지 추천 노드(검색 확장·공식 문서 수집)에서 쓰였다. 원인 분석·공백 분석·근거 검증·리포트는 규칙 계산이라 0초에 가깝다.
- 재기획이 일어나지 않았으므로 기획 생성·평가가 1번씩만 호출됐다. 재기획이 일어나면 Gemini가 2회 더 호출된다(최대 5회).

| 실현 가능성 (15, LLM) | 8~12 | 4회 모두 평가됐다(환산 없음). 가장 많이 나온 이유는 "운영 주체 확인 필요"였다. |

## 5. 발견한 문제와 한계

1. **live에서는 재기획 루프가 한 번도 실행되지 않았다.** 9개 기획안이 모두 77점 이상이었다. 재기획 분기(60점 미만 → 1회 재기획 → 재평가)는 가짜 응답 테스트(`tests/test_graph.py`)로만 확인됐다. 시연에서 재기획을 보여 주려면 저장된 offline 예시 실행을 써야 한다.
2. **규칙 축이 생성된 기획안에 후하다.** 신규성은 9개 모두 만점, 근거성·측정 가능성도 대부분 만점이었다. 기획 생성 지시문이 같은 규칙(공백 원인 대응, 근거 인용, 집단 단위 KPI)을 따르도록 쓰여 있기 때문으로 보인다. 즉 이 축들은 "규칙을 어긴 기획안을 걸러 내는" 역할은 하지만 "좋은 기획안을 가려내는" 변별력은 낮다. 기획안 간 순위는 사실상 타깃 적합성·예산·실현 가능성에서 갈린다.
3. **예산 '회차 연동' 규칙이 온·오프라인 단계형 기획안에서 오탐을 낼 수 있다.** 강남 20대 남성 2안(단계형, 12회 중 오프라인 만남 일부)의 장소 대여비 4회가 "운영 12회보다 적다"며 감점·개선 요청됐다. 장소가 오프라인 회차에만 필요하다면 정상인 계획이다. 예산 회차 개선 요청 5건 중 4건이 단계형 기획안에서 나왔다. 현재 규칙은 활동별 온·오프라인 회차를 구분하지 않는다. 고치려면 활동의 `format`과 회차를 연결하는 입력이 필요하다(후속 과제).
4. **단가가 비어 있어 총액·1인당 비용을 검증하지 못했다.** 예산 상한 입력도 없다(설계 결정 A).
5. **근거 검증 제외가 0건이라 걸러 내는 기능은 live로 확인되지 않았다.** 근거에 없는 수치·URL·금지 표현 제외는 가짜 응답 테스트(`tests/test_grounding.py`)로만 확인됐다.
6. **표본이 4개 집단 × 1회다.** 같은 대상을 다시 실행했을 때 점수가 얼마나 흔들리는지(재현성)는 측정하지 않았다.

## 6. 사람 검토 (양식 — 팀원 작성 필요)

설계 12장의 사람 검토는 아직 하지 않았다. 팀원 3명이 서로의 점수를 모른 채 위 9개 기획안을 채점하고, 평가 노드 점수·순위와 비교한다.
