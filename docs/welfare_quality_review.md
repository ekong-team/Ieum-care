# 복지자원 추천 품질 검증

이 검증은 실제 추천의 적합성과 근거를 사례별로 확인한다. 개인의 복지 자격이나 고립 예방 효과를 입증하지 않는다. 최신 분석 기반 점검과 고정 사례 비교를 함께 사용하며, 목적을 전체로 통일하고 실제 완료 판정의 지역·연령·성별·위험도·원인 맥락을 보존한다. 아래 4개 고정 사례는 비교용이며 운영 추천 대상이나 우선순위를 고정하는 설정이 아니다.

## 최신 분석에 따라 검증 대상 준비

```powershell
# 인자 없이 실행해도 동일하다. 최신 완료 분석을 읽고 계획·입력·빈 검증표만 준비한다.
python scripts/integration/validate_welfare_quality.py --latest-plan
```

완료 판정 목록의 **공동 1순위 전원**을 먼저 포함한다. 이후 선택 목록에 아직 없는 지역·연령·성별·위험 단계를 가장 많이 보충하는 집단을 하나씩 포함한다. 추가 조건 수가 같으면 원래 1차 순위·분석 ID 순으로 결정한다. 이미 모든 조건이 포함되면 멈춘다. 부분판정·보류는 추천 검증에서 제외하고 건수만 기록한다. 검증 사례의 선정 순서이며 새로운 지원 우선순위나 복지 자격 판정이 아니다. 조건별 범위를 점검하는 방식으로, 모든 조건 조합이나 통계적 대표성을 보장하지 않는다.

`data/processed/welfare_quality/plans/<전체 분석 배치 해시>/plan.json`에 기준월·분석 배치·선택 ID·원래 순위·선정 이유·미선택 ID를 보관한다. 같은 폴더의 `plan.csv`에서 선정 목록을 표로 볼 수 있다. 선택된 각 집단의 요청은 `AUTO-<분석 ID 해시 앞16자>/<배치 앞16자>/attempt-01/`에 준비한다. 기존 검토표와 완료·실패 결과는 다시 준비해도 덮어쓰지 않는다. 검증 도구를 다시 실행해야 새 배치 계획이 생성되며 자동 추천이나 운영 화면 변경은 없다.

실제 검토는 계획에 나온 분석 ID를 하나씩 지정한다.

```powershell
# <분석_ID>는 plan.json의 analysis_id 값으로 바꾼다.
python scripts/integration/validate_welfare_quality.py --analysis-id <분석_ID>
python scripts/integration/validate_welfare_quality.py --analysis-id <분석_ID> --allow-external
```

`--allow-external`만 붙여 계획 전체를 실행할 수 없다. 한 집단을 명시해야 하며, 최신 완료 목록에서 사라진 ID는 오류로 중단한다. 분석 입력이 바뀌면 배치별로 기록을 분리한다. 같은 배치의 추천 변동을 확인할 때만 새 `--attempt` 번호를 사용한다. 데이터 변경에 따른 입력 차이와 같은 입력에서의 검색·모델 응답 차이를 구분해 비교한다. 기본 준비 단계에서는 Tavily·Gemini 호출이 모두 0회다.

## 실행·보관

```powershell
# 기본 동작은 입력과 빈 검증표만 준비한다. 외부 API 호출 없음.
python scripts/integration/validate_welfare_quality.py --case CC30F
# 같은 사례의 실제 Tavily·Gemini 추천 한 번. 다른 사례는 실행하지 않는다.
python scripts/integration/validate_welfare_quality.py --case CC30F --allow-external
```

생성 경로: `data/processed/welfare_quality/<사례>/<분석 배치 앞16자>/attempt-01/`. 원래 입력·분석 배치·1차 순위는 request.json, 추천 원문은 result.json, 상태·시각·외부 호출 횟수는 manifest.json, 원문 대조표는 review.csv다. Git 제외 경로이며 키·원본 개인 데이터는 보관하지 않는다. 기본 캐시가 유효하면 검색을 재사용할 수 있으며 실제 요청 직전 콜백으로 API 호출을 센다. 시도 번호가 같은 완료·오류·진행 흔적은 재실행하지 않는다. 추가 실행이 필요하면 사용자 판단 후 새 `--attempt` 번호로 명시한다. 오류 시 재시도·모델 변경·다른 자료로 대체하지 않는다.

## 후보별 원문 대조

공식 상세 안내를 열어 ①출처 수준 ②지역·연령 ③추가 자격의 조건부 표현 ④연도·종료·모집 상태 ⑤원문에 근거한 추천 이유와 고립 예방 연관성을 확인한다. 현재 확인이 안 되는 모집·자격은 unknown으로 기록하며 적합하다고 추정하지 않는다.

review.csv의 verdict는 `pass`(원문과 맞음), `needs_confirmation`(확인 필요), `fail`(원문과 명확히 다름), `pending`(미검토)로 기록한다. evidence에는 짧은 근거와 원문 위치, note에는 한계·수정 과제를 적는다. 최종 후보 평가는 ‘적절한 검토 후보 / 추가 확인 필요 / 부적절한 추천’ 중 하나로 별도 검토 기록에 남긴다. 단순 실패 항목 수로 자동 최종 점수를 만들지 않는다. 정상 0개도 검색 누락 여부를 확인하며 실제 서비스 부재로 확정하지 않는다.

한 집단의 문제를 확인한 후 나머지 사례로 확대한다. 소수 사례로 정확도·재현율·실제 예방 효과의 전체 성능을 주장하지 않는다.

## 2026-10-23: 최신 분석 기반 검증 목록 준비

현재 로컬 최신 배치 `63a0e71b0b25cb71…`, 기준월 2025-12의 완료 집단 24개에서 7개를 선정했다. 공동 1순위는 춘천시 30대 여성·30대 남성·40대 남성 3개 모두 포함했다. 추가 집단은 강남구 20대 남성, 춘천시 10대 여성, 강남구 50대 여성, 춘천시 60대 이상 여성이다. 전체 목록에서 관측된 지역 2개·연령 구간 6개·성별 2개·위험 단계 1~4를 조건별로 포함한다. 5단계 집단은 현재 없으므로 만들어 넣지 않았다. 부분판정·보류는 각각 0개였다.

이는 현재 자료로 준비한 검증 목록이며 데이터가 바뀌면 다시 선정된다. 외부 API 호출은 0회, 실제 추천 결과 추가 검토는 아직 수행하지 않았다. 기존 CC30F 검토 기록도 유지했다. 준비 도구 테스트 8개로 공동 1순위 누락 방지·데이터/순위 변경·입력 보존·중복 실행 방지·빈 목록 처리를 확인했다.

## 2026-10-23: 출처·수치·대상 조건 보완

특정 사업명이나 지역·연령 사례를 고정하지 않고 실시간 추천의 공통 검사 규칙을 보완했다.

- 시청 대표 화면(`/cityhall/` 등)·목록·보고서를 사업 상세 안내와 구분한다. 대표·목록·보고서는 검색 배경으로 전달할 수 있지만 최종 추천의 출처로 사용하면 `source_not_detail` 사유로 제외한다. URL 형식 기반 분류이므로 모든 사이트의 상세 여부를 완벽하게 판별하는 것은 아니다.
- 중앙 보완 검색을 수행했고 중앙 웹 안내가 있으면 최종 최대 8개 근거 중 최대 2개를 확보한다. 나머지는 기존 상세 단서·자료 종류 우선순위를 따른다. 중앙 자료가 지역의 실제 시행을 보장하지는 않는다. 검색 상한은 Tavily 기본 검색 2회·Gemini 1회로 유지한다.
- Gemini 응답에 같은 URL의 지원 내용·대상 조건 인용문(`description_evidence`, `eligibility_evidence`)을 각각 요구한다. 공백을 정리한 인용문이 해당 URL의 제목·검색 발췌문에 있어야 한다. 없거나 1200자를 넘으면 `quote_not_grounded` 사유로 제외한다. 다른 출처의 문장으로 대체할 수 없다.
- 지원 설명·대상 요약에 포함된 숫자와 단위를 해당 인용문과 대조한다. 기간·신청 방법의 수치는 같은 출처의 검색 발췌문과 대조한다. 원·천원·만원 등은 금액으로 환산해 비교하므로 `1,700천원`과 `1,700,000원`은 같고, 이전 오류인 `1,70,000원`은 다르다. 근거가 다른 수치는 `numeric_claim_not_grounded` 사유로 제외한다.
- 대상·신청 조건에는 모델 요약 대신 검사를 통과한 대상 조건 인용문을 보존한다. 인용문에 포함된 소득·가구·제외 조건이 화면과 기획 전달 과정에서 요약으로 빠지는 일을 줄인다. 상세 정보에서 지원 내용·대상 조건 근거를 확인할 수 있고 새 제외 사유도 한국어로 표시한다.

인용문 일치와 숫자 비교는 **사실성 전체 검증이 아니다**. 발췌문 자체가 일부 조건을 생략할 수 있고, 모델이 원문의 일부만 인용하거나 다른 사업 문장을 고를 수 있다. 한글 수사·복합 금액 표현·부정 조건·시행 지역·현재 모집·실제 개인 자격은 별도 원문 검토가 필요하다. 근거를 확보하지 못하면 후보가 줄거나 0개가 될 수 있으며 실제 서비스 부재를 뜻하지 않는다. 내용을 자동 수정하거나 다른 모델로 재시도하지 않는다.

이 단계에서는 가짜 검색·모델 응답으로 검사하며 실제 Tavily·Gemini 호출은 하지 않았다. 과거 `result.json`·검토 기록은 교정하거나 덮어쓰지 않았다. 변경은 새 추천 요청부터 적용되며 저장된 과거 결과를 소급 검증하지 않는다. 다음은 최신 검증 목록의 한 집단을 명시 실행하고 공식 상세 원문과 다시 대조하는 것이다.

## 2026-10-23: 보완 후 실제 한 건 재검토

## 2026-10-23: 최신 안내 검색과 활동지역 해석 보완

모델에는 활동지역이 거주지가 아니라는 점과 서비스 거주 요건은 별도 확인해야 함을 명시했다. 위험도 연결 결과의 화면 설명에도 이 한계를 표시한다. 개인 자격 미확인 자체와 조건부 검토 후보를 확보하지 못한 상태를 구분하도록 지시했다. 추가 소득·가구·거주·진단 조건을 추정하지 않고 원문이 있는 후보의 확인 사항으로 남긴다. 이는 프롬프트 보완이며 모든 생성 문장의 의미를 서버가 보증하는 것은 아니다.

## 2026-10-23: 검색 출처·AI 보류 이유·서버 제외 기록

## 2026-10-23: 사용자 검토 기록에 따른 검색 확장·본문 보완

사용자가 내려받은 기록은 `analysis_id=null`, `period=null`인 일반 탐색이며 AI 후보 0개·서버 제외 0개였다. 지역 상세 단서 2개로 중앙 검색이 생략됐지만, 단서는 장애인 학습동아리·교육도시사업 안내였다. 심리상담·청년월세 등 다른 안내는 검색 발췌가 짧아 조건·지원 내용을 확보하지 못했다. 이 관찰은 개별 서비스의 현재 운영이나 개인의 자격 판정이 아니다.

4. 소득·장애·가구·학적 상태가 입력에 없으면 ‘자격 미확인’으로 표현하고, 불일치로 단정하지 않도록 모델 지시를 보완했다. 고교 졸업예정자·대학생이라는 이유만으로 30대와 나이 불일치라고 확정하지 않는다. 분석이 연결되지 않은 일반 탐색에서는 소비·이동 감소가 관측됐다고 서술하지 않도록 명시했다. 이는 생성 지시이며 의미 전체의 자동 검증은 아니다.

새 Tavily·Gemini 추천은 실행하지 않았다. 사용자 검색 기록을 오프라인 재생했을 때 기존 상세 단서 2개·일반 안내 단서 0개로 분류되어 중앙 보완 검색 단계로 넘어가는 것을 확인했다. 이 재생에서는 중앙 응답을 빈 가짜 결과로 주었으므로 중앙 검색 품질을 확인한 결과가 아니다. 원문 보완은 가짜 HTML로 수집 상한·실패 보존·인증 미전달·리디렉션 미추적·모델 전달·인용 검사까지 확인한다. 실제 추천 시 Tavily 최대 2회·Gemini 최대 1회에 더해 **무료 공개 HTML GET 최대 2회**가 발생하며 `official_page`로 별도 집계한다. 자동 재시도·추가 모델·유료 추출 API는 없다.

확인 순서: 서버 재시작 → 새로고침 → 1차 우선 대상 목록에서 분석 집단 선택 → 단건 추천 → 기록의 분석 ID·기준월·중앙 검색 여부·본문 수집 상태·최종 후보 근거 대조. 새 조회에서 추천 개수가 늘어난다는 보장은 없으며, 이전 결과와 검색 자료가 다르면 코드 변경만의 효과로 해석하지 않는다.
