# 성별 분리 분석 결과와 작업 설명 — 2026-10-19

## 무엇을 했는가

제공 원본의 남녀 구분을 유지해 월×지역×연령×성별로 다시 집계했다. 기존 합산72건을 지우지 않고 남녀144건을 추가해 총216건을 생성했다.
외부 통계로 성별을 추정하지 않았고, 새 데이터를 추가 검색한 것도 아니다. 원래 가진 통신·카드와 기존 주민등록 인구 배경을 다시 사용했다.
분석버전 activity-review-v2.2-sex-aware, 전체 출력 analysis-bundle-0.3, 팀 입력 TargetProfile-0.2다.
자료에서의 성별은 제공기관 원본 코드다. 개인의 성정체성이나 고립 상태·복지 욕구를 판정하지 않는다.

## 원본에서의 구분과 처리

|자료|원본|출력|계산|
|---|---|---|---|
|통신 연령 자료|MAN/WMAN 연령별 열|male/female|각 성별의 인접 월 공통 위치 유동량 비교|
|카드1|남성/여성|male/female|법인 제외, 성별 개인 결제건수 일평균 변화|
|주민등록 인구|남성/여성/전체|male/female/all|같은 월·지역·연령·성별 배경만 연결|
|시간·요일 통신|성별 구분 없음|지역 공통|성별별 관측처럼 사용하지 않음|

남녀 결제건수의 합계가 기존 합산 결제건수와 정확히 일치하는지 검증했다. 통신 연령 유동량도 남녀 합계가 기존 합산과 수치 오차 범위에서 일치한다.
남녀 변화율을 단순 평균해 합산을 만들지 않는다. 서로의 이전 규모가 다르기 때문이다.

소비3%·유동량3%·큰 감소5%·두 전월 비교 지속이라는 기본 규칙은 유지했다. 남녀를 별도 집단으로 계산하므로 결과가 달라질 수 있지만 단계 기준을 성별마다 다르게 주지는 않았다.
같은 개인의 통신·카드 결합은 여전히 불가능하고 가맹점/관측 지역을 주민 거주지로 확정하지 않는다.

## 실제 결과

기존 합산72건의 단계 값 변경0.
남녀144건:1단계75,2단계13,3단계29,4단계3,5단계0,보류24.
남녀 판정 상태:완료115,부분5,보류24.
합산까지 전체216건:완료173,부분7,보류36.
남녀가 모두 완료인 월×지역×연령 조합57개 중5개에서 단계가 달랐다. 독립된57명이나 성별 효과를 검증한 표본이 아니다.

12월 주요 비교:
|집단|합산|남성|여성|
|---|---:|---:|---:|
|춘천30대|4|4|4|

춘천40대 여성은11월 소비-3.32%,유동량-2.80%로 동시 감소 조건을 충족하지 않았다.12월에는 둘 다 감소했지만 연속 조건이 없어3단계다.
남성은11월 소비-4.35%,유동량-4.22%였고12월에도 둘 다3%이상 감소해4단계다.
여성의12월 감소가 남성보다 작기 때문에3단계인 것이 아니다. 지속 조건의 차이다.
강남20대 남성의12월 유동량은 약-3.03%로 기준 경계에 가깝다. 성별 자체가 위험 원인이라는 결론 대신 민감도와 함께 해석한다.

## 우선순위

남녀24개 집단의1차 순위와 합산12개 집단의 비교 순위를 따로 만들었다. 합산 부모 집단과 남녀 하위 집단을 같은 목록에 섞으면 중복되므로 금지했다.
남녀 목록 공동1순위:춘천30대 남성·여성,춘천40대 남성(모두4단계).
같은 단계는 공동 순위이며 성별 자체에 가중치를 주지 않았다. 복지자원 기반2차 판단은 포함하지 않는다.

## 식별자·상태·근거

예:202512_32010_30G_female.
대상 지역·연령·성별·월이 모두 일치해야 한다.
60세 이상 식별자는 기존 준비본의60GU다. 이전 모듈의60G 표기로 배경 연결이 누락되던12개 합산 조합 문제도 수정했다. 단계 값은 바뀌지 않았고 현재216건 모두 인구·달력 배경이 연결됐다.
risk.level은 활동 위축 검토 단계이며 complete는 산식 조건 확인 완료,partial은 확인한 하한,held는 필수 비교 불가다.
근거는E1소비 일평균 변화/E2공통 위치 유동량 변화/E3연속 비교 횟수다.
원인 가설과 가능한 영향 요인은 별도이며 개인의 고립 원인·경제·정서 욕구를 만들어내지 않는다.

## 구현 파일

- scripts/data_processing/build_sex_features.py:원본 성별 재집계·합산 대조·성별 배경 생성.
- ai/analysis_agent/assessment.py:성별별 이력 분리.
- ai/analysis_agent/priority.py:남녀/합산 순위 분리.
- ai/analysis_agent/inputs.py:성별 키·중복·원본/전처리 해시 검사.
- ai/analysis_agent/welfare_handoff.py:현지에게 제안할 성별 보존 입력과 기존 합산 전용 변환.
- scripts/integration/build_welfare_handoff_package.py:전달 ZIP 생성.
- scripts/integration/check_welfare_handoff.py:외부API 없이 ZIP·형식·분석과 요청 일치 검사.
- tests/test_analysis_sex.py:성별 이력·원본 합계·다른 성별 연결 거부·파일 전달 검사.

분석 환경에서 원본 집계를 먼저 실행한 뒤 에이전트 환경에서:
~~~powershell
python scripts/data_processing/build_sex_features.py
./.venv-agent/Scripts/python.exe -X utf8 scripts/integration/run_analysis_agent.py --input-folder data/processed/analysis_sex_inputs_20261019 --output data/processed/analysis_sex_agent_20261019
./.venv-agent/Scripts/python.exe -X utf8 scripts/integration/build_welfare_handoff_package.py
~~~
첫 명령은 pandas/numpy가 있는 기존 분석Python으로 실행한다. 에이전트 가상환경에 분석 패키지가 전부 설치됐다는 뜻은 아니다.
