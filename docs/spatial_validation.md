# 위험도 개발 전 지역 매핑 검증

## 현재 상태

코드·좌표 형식 점검과 실제 행정경계 대조는 별도 단계다.
`validate_regions.py --only coords`는 전자를 수행하며 경계 대조 여부는 판단하지 않는다.
실제 대조는 `validate_regions.py --only boundary`의 별도 결과를 확인한다.
기존 지역 매핑이나 특징 값은 변경하지 않는다.

2026-10-11 점검에서 통신 특징 721,318행, 고유 코드·좌표 조합 126,405개를 확인했다.
동일 코드에 다중 좌표가 연결된 코드는 2,466개(최대 5,020좌표)이며,
같은 월에도 다중 좌표가 존재한다. BLOCK_CD만으로 중복 제거하거나 결합하면 안 된다.
같은 좌표가 서로 다른 앞 5자리 지역코드에 연결된 사례는 없었다.
대상 밖 코드 641행의 월별 연령 유동량 비중은 전체의 약 0.061~0.068%다.
작은 비중이라는 이유만으로 지역 매핑이 검증됐다고 판단하지 않는다.

```powershell
python scripts/data_processing/validate_regions.py --only coords
```

결과는 Git에서 제외된 `data/processed/`에 생성된다.

- `region_mapping_locations.csv`: 고유 코드·좌표, 동일 코드의 좌표 수, 동일 좌표의 지역코드 수.
- `region_mapping_monthly.csv`: 월·코드별 관측 행 수와 연령 유동량, 전체 대비 비중.
- `region_mapping_audit.json`: 원본 특징 해시, 점검 결과와 경계 검증 대기 상태.

## 확보할 경계 자료

[SGIS 자료제공 목록](https://sgis.mods.go.kr/view/pss/openDataIntrcn)은
2025년 센서스용 행정구역 경계(SHP)를 제공한다. 경계 기준은 해당 연도 6월 30일,
제공 좌표계는 UTM-K(GRS80), EPSG:5179다. 자료 신청에는 회원 로그인이 필요하다.

자료신청에서 **센서스용 행정구역 경계 → 2025년 → 시군구** 자료를 신청한다.
가능하면 전국 경계를 확보한다. 강남구·춘천시뿐 아니라 인접 지역의 제외 코드도 확인해야 한다.
다운로드 ZIP 원본을 `data/external/sgis/`에 보관하고, 출처 URL·다운로드 날짜·기준 연도를 함께 기록한다.
SHP와 같은 이름의 SHX·DBF·PRJ 파일을 함께 유지한다.
외부 경계 파일의 Git 포함 여부는 크기와 이용 조건을 확인한 후 결정한다.
현재 받은 2025년 2분기 전국 시군구 ZIP은 Git에서 제외하고 출처 README만 공유한다.

통신 정의서의 `UTM-K` 표기만으로 EPSG:5179가 확정되는 것은 아니다.
경계 PRJ와 제공 데이터의 좌표 기준을 확인하고, 불확실하면 제공기관에 전체 CRS를 확인한다.
좌표가 소지역 중심점인지 관측 격자 대표점인지, BLOCK_CD의 기준 시점이 언제인지도 확인 대상이다.

## 경계 대조 실행

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts/data_processing/validate_regions.py
.venv\Scripts\python.exe scripts/data_processing/validate_processed.py
```

ZIP 내부 기준일은 20250630, PRJ는 EPSG:5179이며 252개 시군구 경계를 포함한다.
`validate_regions.py` 하나가 코드·좌표 점검 → 경계 대조 → 공간 민감도를 순서대로 실행한다.
특정 단계만 다시 실행할 때 `--only coords`, `--only boundary`, `--only sensitivity`를 사용할 수 있다.
통신 좌표는 제공 정의서의 UTM-K를 EPSG:5179로 해석한다. 전체 CRS의 기관 확인과
좌표 대표점 의미는 별도 미확정 사항이므로 조건부 공간 대조로 표현한다.

결과는 `data/processed/spatial_validation_*.csv`와 `spatial_validation_summary.json`에 저장된다.
판정은 내부 일치(`interior_match`), 경계 위(`boundary_match`), 복수 경계,
경계 밖, 알려진 코드의 불일치, 경계 파일에 코드가 없는 경우(`unresolved_code`)로 나눈다.
코드 불일치와 코드 체계 미확정은 같은 문제로 단정하지 않는다.
거리 허용값이나 경계 자동 수정은 사용하지 않는다.

`spatial_sensitivity_metrics.csv`는 기존 코드 기준 집계와 내부 일치 위치만 쓴 집계를 비교한다.
총량·연령 비중·시간대·요일·공통 위치 전월 변화의 차이와 결측 패턴 변화를 확인한다.
원본 특징과 `risk_features.csv`는 덮어쓰지 않는다.

## 2026-10-11 대조 결과와 임시 처리 기준

| 범위 | 내부 일치 | 코드 불일치 | 현 경계에 코드 없음 |
| --- | ---: | ---: | ---: |
| 전체 고유 코드·좌표 조합 | 126,300 | 2 | 103 |
| 강남구·춘천시 대상 조합 | 126,289 | 2 | 0 |

경계 밖이나 복수 경계에 해당하는 점은 없었다. 대상 불일치 2개는 다음과 같다.

- 강남구 코드 `11230760200010000001`, 좌표 (966183.991787, 1940429.147389):
  좌표 판정은 성남시 수정구, 강남구 경계까지 약 8.098m.
- 춘천시 코드 `32010350100010000001`, 좌표 (1002583.991787, 1971829.147389):
  좌표 판정은 가평군, 춘천시 경계까지 약 0.001097m.

두 조합은 6개월에 걸쳐 12행이다. 이를 제외한 민감도 비교에서
연령별 유동량의 최대 상대 차이는 0.0000473%, 전월 변화율의 최대 절대 차이는
0.0000341%p였다. 계산 가능한 값/결측 위치는 바뀌지 않았다.
수치는 현재 자료에 대한 특징 민감도이며 위험 등급 안정성이나 분류 정확도를 뜻하지 않는다.

현재는 기존 코드 기반 특징을 유지하고 두 조합을 예외로 기록한다. 거리가 작다는 이유로
일치 판정으로 바꾸지 않는다. 정식 지역 매핑 확정 전 제공기관에 전체 CRS,
좌표 대표점의 의미, BLOCK_CD의 기준일을 확인해야 한다.

주변 코드 `31370`, `32310`, `32370`, `32380`은 현 경계 파일에 없으며 총 103조합이다.
이들은 기존 최종 특징의 대상 밖 코드로 계속 제외한다. 좌표가 들어가는 시군구는
기록했지만, 공식 코드 변경 이력 없이 과거 코드라고 확정하거나 재매핑하지 않는다.

통신/카드/risk 특징은 수정하지 않았으며, 9개 테스트와 최종 데이터 계약 검증을 통과했다.
공간 대조는 조건부로 완료했으나 예외 처리와 원본 정의 확인까지 확정됐다고 표현하지 않는다.

## 경계를 받은 후 수행할 대조

1. 경계 파일의 기준 연도·좌표계·지역코드 체계를 확인한다. 행안부 코드와 통계청 코드를 혼용하지 않는다.
2. 모든 고유 좌표를 경계와 대조한다. 대상 밖 코드도 포함하고, 경계 위·복수 경계·경계 밖은 별도 기록한다.
3. 코드 기준과 좌표 기준 지역이 다른 위치를 월별 유동량과 함께 확인한다.
4. 경계 근처의 불일치는 좌표 대표점 의미를 확인한다. 임의 거리 허용값으로 통과시키지 않는다.
5. 제외·재매핑이 필요하면 근거와 영향을 기록하고 통합 정제를 다시 실행한다.

## 그다음 진행 순서

1. 지역 매핑 검증과 예외 처리 확정.
2. 해석보류 업종의 포함·제외 기준 확정 및 비중에 따른 민감도 확인.
3. 관측 범위·결측·중복 지표를 점검하고 모델 입력 후보 확정.
4. 정제 결과와 제한 사항을 문서화하고 main에서 커밋.
5. `hyeonji/risk-model`에서 위험도 설계 시작. 정답 라벨 유무와 검증 방법을 먼저 정한다.

위 순서에서 점수·5단계 등급은 마지막 개발 단계에 해당한다.
