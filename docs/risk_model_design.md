# 활동 감소 신호 5단계: 규칙 기반 v1

상태: 소비와 업종 제외 조건을 사용자에게 확인한 뒤 `activity-decline-v1`으로 구현했다.
개발 브랜치는 `hyeonji/risk-model`이며 고립의 정답/확률을 학습한 모델은 아니다.

## 판단 대상과 용어

한 건은 월×지역×연령 집계 조합이다. 개인의 고립 여부나 실제 고립 확률로 해석하지 않는다.
현재 팀 제안은 두 지표의 감소·동시 감소·지속성을 사용하는 규칙이다.
별도의 4축 점수나 가중치를 먼저 추가하지 않는다.

- 이동: `통신_연령유동량_전월변화율`. 동일한 개인의 이동 횟수가 아니라
  인접 두 달의 공통 코드·좌표에서 관측한 연령별 유동량 변화다.
- 소비: `카드1_전체_결제건수`의 전월 변화율. 금액이나 사회활동 후보 건수가 아니다.
- 감소율: `(이번 달 값 / 지난달 값) - 1`. -0.03은 3% 감소, -0.05는 5% 감소다.
- 3%·5%는 팀 제안 임계값이다. 실제 고립 위험의 검증된 기준이라고 표현하지 않는다.

## 팀 제안 표와 계산 규칙

`C[t]`는 소비 변화율, `M[t]`는 통신 유동량 변화율이다.
`B[t] = (C[t] <= -0.03) AND (M[t] <= -0.03)`으로 둔다.
3% 이상 감소는 정확히 -3%인 경우도 포함한다. 화면에 반올림한 값으로 비교하지 않는다.

| 단계 | 기본 조건 | 설명 |
| --- | --- | --- |
| 1 | `C[t] > -0.03` AND `M[t] > -0.03` | 해당 기준의 감소 신호 없음. 안전·정상 확정이 아님 |
| 2 | 두 지표 중 정확히 하나만 -3% 이하 | 한쪽 감소 |
| 3 | `B[t]`가 참이며 상위 단계 조건을 충족하지 않음 | 두 지표 동시 감소 |
| 4 | `B[t]`와 `B[t-1]`이 참이며 5단계 조건을 충족하지 않음 | 동시 감소가 연속 두 번의 월 비교에서 유지 |
| 5 | 4단계 조건 + 현재 `C[t] <= -0.05`, `M[t] <= -0.05` + 업종 제외 점검 | 지속·큰 감소·업종 점검 조건을 함께 충족 |

상위 단계부터 **5 → 4 → 3 → 2 → 1** 순으로 확인해 가장 높은 충족 단계를 부여한다.
5단계 업종 점검은 전체 개인 결제건수에서 두 원본 업종을 제외한 소비도
연속 두 번의 전월 비교에서 각각 3% 이상 감소하는 조건이다.

## 연속 감소와 판단 보류

예를 들어 9월의 지속 감소는 7→8월과 8→9월의 두 변화율을 검사한다.
같은 지역·같은 연령 조합을 비교하고 달이 연속인지 확인한다.
통신의 각 전월 변화는 해당 두 달의 공통 위치를 사용하며, 세 달 전체의 동일 위치를
고정한 비교와는 다르다. 위치 구성 영향은 관측 품질 맥락으로 함께 제공한다.

| 시점/문제 | 처리할 원칙 |
| --- | --- |
| 7월 | 이전 달이 없어 단계 판단 보류. 1단계나 변화 없음으로 대체하지 않음 |
| 8월 | 1·2단계는 완료 판정 가능. 두 지표 동시 감소 시 확인된 하한 3단계를 부분판정으로 표시. 4·5단계는 이력 부족 |
| 9월 이후 | 연속 자료가 있으면 4·5단계까지 평가 가능 |
| 현재 필수 지표 결측·전월 분모 0 | 임의 대체하지 않고 판단 보류 |
| 과거 월 누락 | 현재 비교 자체가 불가하면 보류. 현재 비교만 가능하면 상위 단계 이력 부족을 부분판정으로 표시 |
| 업종 제외 검사가 필요한데 계산 불가 | 4단계까지 확인되면 4를 부분판정으로 표시. 계산 불가를 5단계 조건 불충족으로 바꾸지 않음 |

`판정상태`는 `판정완료`, `부분판정`, `판단보류`로 나눈다. 부분판정의 `위험단계`는
현재 자료에서 확인된 하한이며 최종 확정 단계가 아니다. 후속 Agent도 이 상태를 함께 읽어야 한다.
조건식에는 참/거짓/미확인의 세 상태를 사용한다. AND 조건에서 하나라도 거짓이면 전체는 거짓이고,
거짓 없이 미확인이 남으면 전체도 미확인이다. 따라서 5단계 불충족과 검증 불가를 구분한다.

관측률·해석보류 비중이 높거나 낮다는 이유만으로 단계를 올리지 않는다.
현재 관측률을 등급 산출의 차단 조건으로 사용할 임계값도 정하지 않았다.

## 5단계 업종 제외 점검: 확정한 해석

전체 개인 결제건수에서 골프·놀이동산 관련 두 업종 항목만 제외한다.
사회활동 후보 업종 합계에서 제외하는 방식은 사용하지 않는다.

현재 확인한 원본 업종 표기는 `실내/실외골프장`, `종합레저타운/놀이동산`이다.
후자는 종합레저타운과 놀이동산이 묶인 항목이므로 놀이동산 거래만 따로 구분할 수 없다.
두 원본 업종 항목 전체를 제외하며 결과 요약에도 실제 제외 항목명을 기록한다.

기존 `card_features.csv`에는 운동·문화 그룹 합계만 있어 두 업종만 정확히 뺄 수 없다.
카드1 원본에서 개인 거래만 사용하여 월×가맹점지역×연령×업종으로 재집계하고,
기존 전체 합계와 일치하는지 확인한 뒤 업종 제외 값을 계산한다.
이번 달뿐 아니라 비교 대상인 과거 달에도 같은 제외 기준을 적용한다.
기존 전체 특징이나 업종 분류 정의를 바꾸지 않는다.

## 실행과 결과

```bash
python ai/risk_model/classify_risk.py
python -m unittest discover -s tests -v
```

입력은 정제된 `risk_features.csv`, 카드1 원본 TXT, `preprocessing_manifest.json`이다.
정제 기록의 상태와 입력/공통 코드 해시를 확인하고 카드 원본에서 개인 거래를 재집계한다.
72개 키와 전체 결제건수가 기존 특징에 일치하는지, 재계산한 소비 변화율도 같은지 확인한다.
원본·기존 특징·정제 manifest는 덮어쓰지 않는다.

결과는 Git에서 제외된 `data/processed/risk_model/`에만 저장한다.

- `risk_levels.csv`: 기본/업종 제외 건수, 현재/전월 변화율, 조건별 참·거짓·미확인,
  위험단계·판정상태·판단근거·관측 품질 맥락.
- `summary.json`: 실행 상태, 규칙 버전·임계값·제외 업종, 판정 분포, 입력/출력/코드 해시.

실행 중 상태는 running, 실패하면 failed로 기록한다. 이전 CSV가 남아 있더라도
summary가 passed가 아니면 최신 결과로 사용하지 않는다.

## 검증 범위와 다음 단계

원본 합계 보존, -3%/-5% 경계값, 상위 단계 우선순위, 그룹 분리, 미래 값의 과거 판정 영향,
3개월 지속성, 결측·누락 월·전월 0, 업종 제외 계산을 테스트했다.
다음은 임계값 민감도, 단계의 월별 전이, 월 길이·계절성·관측 위치 변화 등 대안 설명을 점검하는 것이다.
원시 월 건수는 월 길이 영향을 받으므로 일평균 소비 기준과의 민감도도 별도 검토한다.
v1에서 일수 보정·계절 보정·가중치·학습은 적용하지 않았다.
외부 근거와 전문가 검토, 정답 라벨 확보 전 실제 고립 분류 성능을 검증했다고 표현하지 않는다.

출력에는 단계뿐 아니라 지표 정의·변화율·조건별 충족 여부·이력 상태·관측 품질·
업종 제외 범위·판단 근거를 남긴다. 0~100점이나 확률은 별도 근거 없이 추가하지 않는다.
현재 정답 라벨이 없으므로 규칙 테스트와 안정성 검증을 정확도·F1 검증으로 부르지 않는다.
